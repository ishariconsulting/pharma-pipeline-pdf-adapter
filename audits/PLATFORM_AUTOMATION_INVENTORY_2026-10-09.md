**Scope:** Ishari Consulting production base `appzteNR0u0ywm9Zz` (configuration examined 9 October 2026).
**Mode:** READ-ONLY inventory. **No automation was edited, disabled, published, deleted, cloned, or triggered by this audit.**

## Executive decision
96 automations: **27 ON** and **69 OFF**. Review classification: **25 OPERATE**, **2 ON_HISTORICAL**, **16 RETAIN_GUARDED**, **45 ARCHIVE_FIRST_REVIEW**, **8 PRIORITY_RETIRE_REVIEW**. These are **not deletion authorizations**; retirement requires preserving full script+trigger+results, checking cross-module dependencies and obtaining explicit user approval.

## Method and limits
Each of the **96 full automation configurations** was read individually via Airtable, including trigger type, graph actions, custom-script content/versions and published-vs-draft difference. Recent run history was additionally inspected for **all 27 ON workflows** and a failure-only check for selected problem workflows. This is an architecture/inventory audit, not a line-by-line security proof, test execution of OFF flows or verified data-quality assessment. A platform-reported successful run need not mean semantically correct output. Run history is retention-limited; no inference of permanent non-use from an empty recent history.

## Recommended controlled rationalisation
**Wave 0 — Evidence backup and safety:** capture the full draft and published source, trigger conditions, input variables, saved historical outputs and last known usage for each candidate; preserve any previous approved cohort/Portfolio release receipts. Protect historical queue and clinical relationships.

**Wave 1 — Reliability:** investigate currently ON workflows with failed runs; check source-specific errors, write controls and actual downstream data. An apparent success is not full production quality.

**Wave 2 — Eight priority retirement reviews:** identify exact replacement, downstream dependency and backups for each `PRIORITY_RETIRE_REVIEW` row below. This is a shortlist, not permission to delete.

**Wave 3 — Historical canaries:** retain code/results in versioned repository; only then consider archiving or removing 45 OFF diagnostics after a proven shared alternative exists. Keep 16 reusable guarded workflows OFF until separately approved.

**Approval boundary:** No Portfolio master writes, Candidate edits, automation deletions/enables, trigger changes, GitHub merges or production deployments authorised by this assessment. Original current production remains unchanged.
